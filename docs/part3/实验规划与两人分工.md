编制日期：2026-11-18（北京时间）。本文是基于本地代码、结果和进度记录制定的计划；本次没有启动新模型实验，也没有核验远端服务器实时状态。按两人、约 10 个工作日规划，实际截止时间、API 预算和每日算力时长尚未提供。

## 1. 核心判断

**项目结构：Part 2 已完成，下面所有新比较与探索均归入 Part 3。** Part 2 只作为冻结的官方 AnomalyDINO 基线，Part 3 在它之上做受控模型比较与新方法探索。\r\n\r\n建议把 Part 3 的研究问题定为：**少样本工业异常检测中，局部视觉证据、语言语义和主动复查分别有什么作用？它们在准确率、定位和成本之间能否形成互补？**

老师提到的模型多样性、直接询问多模态 AI、双分支融合，分别对应三个可以独立回答的研究问题：

1. RQ1：固定局部匹配方法时，更换视觉表示后效果如何？
2. RQ2：不依赖传统异常热图，多模态模型能否仅凭正常参考图与测试图做有效检查？
3. RQ3：局部匹配与多模态判断是否互补？融合何时有效、何时有害？
4. RQ4（探索）：让模型放大检查可疑区域，或只在必要时调用模型，能否改善小缺陷识别或降低成本？

这里要调整一个表述：只比较不同模型，不能直接证明“我们的方法对所有模型都有效”。要支持方法可迁移，需要在至少两个视觉骨干上分别比较“单分支”和“加入同一种融合机制后的结果”。无提升和负结果也应保留。

## 3. 固定实验协议

### 3.1 数据和统计

- 六类：candle、capsules、cashew、chewinggum、fryum、pipe_fryum。
- shot：1、2、4、8；seed：0、1、2。全网格为 72 个类别组合；每个模型的完整评测是 12 × 960 = 11,520 个测试配置实例。
- 每个 shot/seed 都有相同的 960 张测试图。类别数量：200、160、150、150、150、150。
- 直接读取已归档 refs，不依赖“同一个 seed 理应选到同一批图”。现有规则是排除校准图后 `pool[seed*shot:(seed+1)*shot]`，不同 shot 的参考集并非普遍嵌套；保持历史协议，不静默改成嵌套采样。
- 三 seed 主要反映参考图选择变化；VLM 解码随机性另设 repeat_id，不能混为三次独立测试集实验。
- 每类先算 AUROC，再做六类宏平均；每个 seed 得到一个宏平均，最后在三个宏平均上算 mean/std。与现有表格一致，明确 std 的 ddof。
- Pixel AUROC 包含正常测试图的全零 mask；保持现有 448×448 评价网格及插值、平滑口径。严格校验应有文件数，缺文件直接报不完整，不能静默跳过。
- 主指标 Image AUROC；具有有效空间输出的方法再报 Pixel AUROC。可加 Image AUPRC、固定正常校准阈值下的 FPR/FNR、小缺陷子集表现。不能用高 Pixel AUROC 掩盖图像漏检。

### 3.2 校准与 shot 的实际含义

现有每类前 20 张正常训练图已从参考池排除，原用于阈值校准。新实验可以预先约定将其用于分数尺度估计，但必须对全部方法一致披露：**n 张参考图 + 20 张正常校准图/类**，而不是严格只有 n 张正常图可用。校准图不能加进 memory bank 或作为 VLM 上下文参考图；校准图作为 query 时，每次仍只看到对应 n 张参考图。

禁止用测试标签挑融合权重、prompt、裁剪策略、阈值或模型。仅有正常校准图无法验证“异常排序最优权重”。因此主结果预注册 α=0.5；α∈{0,0.25,0.5,0.75,1} 全部报告为敏感性分析，不把测试集最高点称为部署最优值。若必须选择权重，另建与测试隔离的开发集，并披露新增异常标签或合成异常的来源。

### 3.3 公平性要分两个层次

1. **骨干受控实验：** 固定最近邻、特征归一化、距离度量、参考增广、评分规则和空间处理；比较 DINO 与 CLIP 等表示。DINO 特有 PCA 阈值不能直接视作适用于所有模型。主受控对比可统一关闭特征相关前景掩码，并额外运行相同设置的 DINO 对照；官方 agnostic 结果作为完整系统基线保留。
2. **完整系统对比：** 官方 DINO、直接问 Qwen、ROI 复查等允许原生处理方式不同，但需完整列出输入分辨率、额外视图、文本、训练资源和耗时。结论称为系统比较，不归因于单一骨干差异。

统一 448 的评价图不代表所有模型输入已相同。CLIP 的输入尺寸、位置编码插值和 patch 接口必须先验证。若只能稳定运行原生 224 输入，新增 DINO@224 作为匹配对照；DINO@448 官方结果另列。不能把 DINO@448 对 CLIP@224 的差异直接解释为表示优劣。

最终最低交付是 E0–E4；推荐完成 E5 和 E6 中至少一个。若报告想强调“不局限于 DINO”，应优先 E5；若强调新颖交互方式，优先 E6。E7 可先只做明确标注的子集探索，不要求一开始就承担完整 API 网格。

### E1：替代视觉表示

首选 CLIP 类视觉编码器：它同时支持“纯视觉特征对照”和后续文本语义探索。官方 CLIP 的 encode_image 返回图像特征，不能直接当作 patch anomaly map；需要实现并核验空间 token 提取、网格顺序和预处理。初期固定一个 checkpoint、最后一层空间特征，避免立刻扫描很多层和尺寸。[官方 CLIP](https://github.com/openai/CLIP)

先完成纯视觉 CLIP-patch-kNN。随后可选做 CLIP 文本分数：正常/缺陷提示集合与图像或窗口相似度，作为低成本语义基线。WinCLIP/WinCLIP+ 已研究窗口/patch/文本及少量正常图信息，可以借鉴，但只有实际遵循其实现并复核协议才称“复现 WinCLIP”；自定义版本必须命名为自己的 CLIP baseline。[WinCLIP 论文](https://arxiv.org/abs/2303.14814)

若 CLIP patch 接口短期受阻，可先使用代码中已有 ViTWrapper 做替代骨干烟雾测试；仍需核验尺寸和掩码差异，不能直接把 wrapper 存在当成可比较实验完成。

### E2：独立的多模态语义检查

选一个可取得权重、能在共享服务器预算内运行的 Qwen-VL Instruct checkpoint，冻结模型 ID、revision、精度/量化、processor 版本与视觉 token 限额。先验证多图输入，尤其 8 张参考图 + 1 张测试图。不要因为服务器曾有约 49GB 显存，就默认当前可用或九图一定能装下。

Qwen 官方资料提供多图处理、视觉定位和结构化输出相关用法，也列出 ModelScope 获取路径；这可作为旧记录中 Hugging Face 不可达时的候选方案，实际可达性必须重新检查。[Qwen3-VL 官方仓库](https://github.com/QwenLM/Qwen3-VL)

每次输入：类别名称、对应 n 张正常参考图、一个 query、固定检查提示。独立 E2 不提供 DINO 热图或分数。主要输出为连续 anomaly_score、短证据说明、可选 regions；模型自报 confidence 另存，不能视为校准后的概率。结构化 JSON 是输出约束，仍须做解析校验。

最少的 prompt 消融只保留：直接检查 vs 与正常参考图比较。0-shot 可以作为额外行，但不冒充 1-shot。禁止在测试错误上反复改 prompt，再把改后的同一测试集当独立验证。

### E3–E5：先融合图像分数，再研究空间融合

对每类、shot、seed、分支，用固定正常校准图的 query 分数估计中位数与 MAD：

`z_b = (score_b - median(calibration_b)) / max(1.4826 * MAD(calibration_b), epsilon)`

两分支都先变换，约定分数越大越异常。尺度退化时按预注册规则回退到标准差，再退化到固定 epsilon，并记录；不能观察测试结果后选归一化方法。20 张正常图的尾部分布估计不稳，要如实说明。

`fused_score = α * z_visual + (1-α) * z_vlm`

主结果 α=0.5；五个权重由已保存的逐图预测离线计算，不重复调用 VLM。α=1 和 α=0 应分别恢复相应单分支的类内 AUROC，作为数据对齐与方向检查。

只融合图像分数时，不声称 Pixel AUROC 改善。最终展示可写“图像分数来自融合、定位图来自视觉分支”，两者明确分开。

若 VLM 真输出 region，可另设“框栅格化的粗定位基线”，报告由框构造的连续/常数区域图及其规则；它不是精细分割。不得将全图 anomaly_score 均匀涂满图片称为定位。给整张 DINO 图乘一个正标量只改变图间尺度，可能改变 pooled pixel AUROC，无法证明图内定位变准。

## 5. 探索性想法池：让信息与交互方式也变化

| 方向 | 如何做 | 科学问题与必要对照 | 成本/优先级 |
|---|---|---|---|
| 局部主动复查 | 从 DINO 图找 top-k 非重叠可疑区域，将全图 + ROI 交给 Qwen；坐标来自推理而非 GT | 对比全图、固定网格裁剪、DINO 引导裁剪；收益来自放大还是选区？ | 中，首选探索 |
| 文本正常规范 | 从当次 n 张正常参考图生成形状、表面、数量等简短规范，再检查 query | 与无规范版本比较；生成规范不能读取更多正常图或测试标签 | 低至中，P1 |
| 低成本 CLIP 文本语义 | 固定 normal/defective 文本集合，与全图或窗口特征比较 | 不用大生成模型是否已有语义增益？ | 低，P1 |
| 按需调用 VLM | 根据视觉分数距正常校准阈值的距离，预先定义复查区间；其余保留视觉分数 | 性能 vs 调用率、延迟、成本曲线；预算公平对照随机调用 | 中，P1/P2 |
| 分支分歧复查 | 两个分支不一致时让 VLM 再看全图及局部图 | 首轮必须先运行两分支，因此不节省首轮调用；要统计复查总成本 | 中高，P2 |
| 参考图顺序/布局 | 固定同一参考集，变换顺序；单独多图 vs 拼图展示 | 语义分支是否依赖上下文布局？拼图会压缩每图细节，需披露 | 中，P2 |
| 反事实缺陷 | 在正常图合成小划痕、缺口或污点，控制面积和对比度 | 只作诊断/独立开发，不能替代真实 VisA 主测试；保留合成局限 | 中，P2 |
| VLM 框 + 分割器 | VLM 预测框，再用分割器细化 | 框到 mask 的误差来源；标明额外模型、资源，不用 GT 框 | 高，P2 |
| 专用异常 VLM/CLIP 方法 | 加一个有现成权重且可获取的专用方法 | 区分额外异常监督、辅助数据与通用模型的资源条件 | 高，非首轮 |
| 原 DINO 多层融合 | 复用现有 L6/9/12 脚手架 | 低成本局部特征消融，不能替代老师要求的语义分支 | 低，但在 E0 后 |

不建议首轮同时做多个大模型微调、复杂可学习融合、扩散重建和完整分割链路。先用冻结模型与明确消融验证研究问题；有结果再决定是否值得训练。

## 6. 分阶段进程与止损点

### Part 3 执行阶段 A：第 1–2 天，建立可比较接口

1. 共同核对本地与远端状态，确认 refs、数据和原始 maps 是否仍在。历史 `/tmp` 路径可能已失效。
2. A 对同一批约 10 张图片逐步比较官方/缓存分支；查参考图、预处理、旋转、掩码、特征、距离、图、分数，记录首个分歧。
3. 预设通过标准：相同 refs 和覆盖数；逐图分数/maps 在固定容差内一致（例如初始 float32 1e-5，具体结合库精度预注册）；一个完整 1-shot seed0 的 Image/Pixel AUROC 相差不超过 0.01 个百分点。仅 AUROC 相同不足以证明路径等价。
4. 若到第 2 天仍无法对齐：保留官方路径作 DINO 分支，导出官方逐图分数并离线融合；缓存实现不进入主结论。不能让缓存调试阻断全部多模态工作。
5. B 完成多图 VLM 烟雾测试：1/4/8 张参考图、坐标格式、异常分数分布、JSON 解析、延迟和峰值内存。

交付：protocol_v1、reference_manifest、prediction_schema、environment_snapshot、parity_report、VLM smoke report。

### 阶段 B：第 3–4 天，小规模探索

建议用 candle（当前 1-shot image 相对弱）与 capsules（1-shot pixel 相对弱），固定 1-shot/seed0；每类最多约 20 张正常 + 20 张异常 query 作为先导子集。只要这些图片参与 prompt/策略选择，就将其标记为开发子集，并从后续确认性评测中排除，重算所有对照的同一子集指标。全 960 图的结果可另作含开发图的描述性表，不能隐瞒重复使用。

不愿改变完整 960 图协议时，另一条更保守路线是：先导仅使用训练正常校准图和训练图生成的诊断缺陷，全部 prompt/参数预先冻结，再首次查看完整测试结果。

按以下因素选可执行配置：有效输出率、是否大量输出相同分数、8-shot 是否能完成、时间/显存、与视觉分支是否有不同错误。不能只留下看起来提升的例子。建议有效 JSON ≥99%、失败均可追踪；质量门槛是工程门槛，不预设必须超过 DINO。

先导后冻结一个替代视觉模型、一个 Qwen 配置、一个基础 prompt、一种归一化和一种 ROI 规则。不继续无限试 prompt。

### 阶段 C：第 5–7 天，完整主实验

- A：完成替代视觉表示网格，整理官方 DINO 的逐图预测。
- B：完成 Qwen 的四 shot × 三 seed 推理；第 5 天先检查 8-shot 资源，避免最后才发现上下文或显存问题。
- 两人离线完成 α 敏感性、E5 的跨骨干融合以及一致覆盖检查。
- 未完成全网格的方法明确列为 subset/pilot，不用少量样本的成绩与完整 960 图直接排名。

### 阶段 D：第 8–9 天，关键探索与错误分析

- 首选完成 ROI 复查，并加固定网格裁剪对照；若资源不足，先固定 1-shot/seed0、六类完整测试，明确只支持这一设置的结论。
- 若有 API 预算，在相同固定子集做 GPT 对照；先测 20 次调用估算预算，再决定是否扩展。
- 保留四种案例：两分支都对、只有视觉对、只有 VLM 对、两者都错。对融合新增误报和新增漏检同样展示。
- 分析至少四类现象：细小纹理缺陷、形状/结构缺陷、正常姿态/光照变化、背景干扰。子组依据 GT/mask 只能用于评价分析，不能反馈到已冻结推理策略。

### 阶段 E：第 10 天，收口与报告

共同审阅主表、按类表、shot 曲线、α 曲线、调用成本、失败记录。A 主讲局部表示/协议，B 主讲多模态/融合；双方必须都能解释完整系统。明确哪些完成、哪些仅探索、哪些失败，以及额外正常校准资源。

## 7. 两个人的详细分工

暂用成员 A、成员 B，不假定具体姓名或能力强弱；可根据谁熟悉现有 GPU/代码调整。

| 工作包 | 成员 A：视觉与评测负责人 | 成员 B：多模态与协作推理负责人 | 完成证据 |
|---|---|---|---|
| 状态审计 | 核对官方结果、refs、缓存差异 | 核对权重可获得性、API/多图能力 | 状态表，无计划冒充结果 |
| 协议 | 主写数据清单、评价、统计和缺失检测 | 主写 VLM 输入、prompt、资源披露 | 双方签字冻结 protocol_v1 |
| 视觉分支 | DINO parity；CLIP adapter；kNN/maps；可选 ViT | 复核接口能按 image_id 读取 | 一完整 cell + 可核验逐图输出 |
| 语义分支 | 提供 refs/query 清单和类别元数据 | VLM runner、JSON 校验、缓存、失败重试 | smoke report + 可复用预测 |
| 全网格 | 管理视觉实验和 maps 导出 | 管理 VLM 实验、token/耗时记录 | 每方法 12 个配置完整覆盖 |
| 融合 | 实现 join、校准、α 离线扫描、评价 | 核对分数方向、语义输出和端点 | 端点还原单分支，主 α 预注册 |
| 探索实验 | 输出 ROI；固定网格对照；空间图评价 | ROI prompt、复查策略、可选 GPT 对照 | 全图/ROI/固定网格三者同集 |

日常协作：每天一次 15 分钟对齐，只汇报“完成证据、下一依赖、阻碍”；当日结果及时备份。A 审 B 的 prompt 与失效处理，B 审 A 的 refs、评价和融合，避免只有本人理解自己的半边。

共享 A6000 的历史约束是一个 GPU 作业；运行前重新检查，安排串行时段。视觉特征只提取一次，多 shot/seed 重建 bank；VLM 完成推理后按预测缓存离线扫权重。两个人可以同时写代码/分析，但不能默认同时占用共享 GPU。

## 8. 接口、目录和成本账本

建议在 `p2-anomaly/` 新增（均为规划中的文件，不表示已创建）：

```text
configs/extension_protocol.yaml
manifests/{references,calibration,queries}.jsonl
prompts/{inspection_v1,roi_review_v1}.txt
src/{visual_adapters,vlm_client,prediction_schema,score_fusion}.py
run_visual_baselines.py
run_vlm.py
evaluate_predictions.py
results/extensions/<experiment_id>/
    config.json
    predictions.jsonl
    calibration_predictions.jsonl
    metrics.json
    failures.jsonl
    cost_summary.json
```

通用预测字段：experiment_id、category、image_id（不含 good/bad 等真值暗示）、shot、reference_seed、repeat_id、reference_ids、model_id/revision、prompt_hash、anomaly_score、decision、regions、map_path、status、latency_ms、input/output_tokens、peak_gpu_memory、preprocessing/config_hash。输出可带简短 evidence，但真值 label、GT mask 和类别文件夹 good/bad 不进入 prompt。VLM 每个 query 使用独立上下文，禁止混入上一张测试图。

VLM 原始响应另外保存；若解析失败，最多按固定策略重试，并记录全部调用。失败不能当正常、不能静默删掉困难图片。固定失败回退策略后同时报告失败率和含回退结果的系统指标；若采用 complete-case 指标，所有对照在相同成功交集上重算，并作为补充表。

缓存键必须包含模型/revision、量化、prompt、图像内容 hash、参考图及顺序、预处理、解码设置，不能只看测试图文件名。

预算：一套主 VLM 完整网格 11,520 次测试调用；若每类 20 张校准图均作为 query，另有 6×20×4×3 = 1,440 次，总计约 12,960 次，尚不含重试、ROI 或 repeat。0-shot 若输入完全相同可复用缓存，但不要虚构三 seed 随机性。

先导测得平均每次 t 秒，则串行总推理约 `12960*t/3600` 小时；若 t=5 秒约 18 小时，t=20 秒约 72 小时。这只是预算例子，不是实测时间。API 成本必须按实际图像/文本输入、输出 token 和重试估算，不能只按调用次数计费。

报告时分开记：参考库/特征构建、每图在线推理、端到端时间（含网络/裁剪/解析/重试）、均值和 p95、总 GPU 峰值、调用率、token 和金额。远端 API 服务显存不可见，写 N/A；本机客户端显存不能冒充服务端显存。缓存后的 α 计算时间不当作整个融合系统推理时间。

## 9. 交付标准与结论边界

最低完成：官方基线可追踪；一个替代视觉表示；一个独立 Qwen 语义分支；固定权重融合及完整 α 曲线；相同评测覆盖；逐图预测；错误与成本分析。

推荐图表：主结果按 shot 的 mean/std；每类别结果；两个视觉骨干各自融合前后；α 敏感性；全图与 ROI 对照；准确率-调用成本曲线；四类分歧案例。Pixel AUROC 表只收录真正有空间输出的实验。

表述应随结果变化：

- 融合有效：说明具体类别/shot、增益、退化和成本，不写普遍优于。
- 融合无效：分析错误重叠、自报分数不稳定、尺度问题；如实报告。
- Qwen 弱但 ROI 有帮助：结论聚焦局部证据引导，不能把独立语义分支包装成高精度。
- 只完成一个骨干融合：只能证明这一配置可行，不能称跨骨干泛化。
- 只在子集做 GPT：只能是跨 VLM 探索，不能声称完整协议已验证。

当前适合的答辩表述：

> We have completed the official DINOv2-based baseline across four shot settings and three reference seeds. Following the feedback, we plan controlled comparisons with another visual representation, direct multimodal inspection, and fusion of local and semantic evidence. We will evaluate whether the branches are complementary and report both gains and failure cases under a shared protocol.

## 10. 外部依据与原创范围

本规划中的 ROI 复查、文本规范、按需调用和固定权重组合，是结合项目状态提出的候选实验设计；本次未开展全面文献新颖性审查，不能据此宣称首创。

- [AnomalyDINO 官方代码](https://github.com/dammsi/AnomalyDINO)：现有方法来源。
- [CLIP 官方代码](https://github.com/openai/CLIP)：视觉/文本编码接口依据。
- [WinCLIP / WinCLIP+ 原论文](https://arxiv.org/abs/2303.14814)：窗口、文本与正常参考图结合的相关工作；不把论文的全数据集成绩直接与本项目六类表对比。
- [Qwen3-VL 官方代码与示例](https://github.com/QwenLM/Qwen3-VL)：多图与视觉定位能力、模型获取方案的依据；工业微小缺陷表现需本项目实测。
